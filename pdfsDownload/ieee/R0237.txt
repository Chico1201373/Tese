 Abstract- Chatbots powered by LLMs have become popular due to 
their scalability and instant reply feature. There can be many 
security issues associated with LLM-based chatbots, which emerge 
in the interaction between the LLM-based model and other 
software components. One major problem is that chatbots can be 
attacked using prompt injection, jailbreaks, and harmful queries. 
These attacks can change the chatbot behavior and may lead to 
wrong answers or leakage of sensitive information. This makes 
security very important in such systems. Existing methods improve 
the chatbot performance using techniques like modular design, 
Retrieval-Augmented Generation (RAG) and input filtering for 
security. However, most of these methods use a single model and do 
not have strong real-time protection, making them weak against 
advanced attacks. Hence, this work proposes a Dual-LLM 
architecture where security is handled as a separate component for 
protection against real time threats. A classification model is 
designed to check the user input queries using threat categories and 
a confidence score is evaluated to block the harmful inputs. Only 
safe queries are sent to the response model, which uses a controlled 
RAG system to generate accurate answers. The system is built as a 
step-by-step pipeline combining classification and response 
generation. The results show an accuracy of 90% in detecting 
threats which leads to reduction of unsafe responses. 
Keywords- Large Language Models, Chatbot Security, LLM 
Security Prompt Injection, Retrieval-Augmented Generation, Threat 
Detection, Suspicious pattern, Similarity search. 
I.  INTRODUCTION  
The use of chatbots based on large language models (LLMs) 
has become common in areas like education, customer services, 
and organizational functions  as it provides immediate 
conversational assistance [1][2]. Within the academic context, 
chatbots are used to assist with queries related to admissions, 
courses, and other processes. Nonetheless, despite their benefits, 
the fact that such bots have access to open interfaces makes them 
vulnerable to many forms of security attacks [3][4]. 
The primary focus in the early stages of Chatbot creation was 
on its efficiency and usability, with basic security considerations 
limited to primitive input validation [5]. Over the time, as 
advancements were made in the domain of chatbots, complex 
mechanisms such as modular pipelines and RAG has been 
utilized by contemporary frameworks [6]. This allowed chatbots 
to fetch their answers not only from structured but also from 
unstructured datasets. while such changes certainly made 
chatbots more efficient and precise, they simultaneously provided  
 more access for attackers to gain access to chatbots. Among 
the most significant threats posed in the area of open access 
chatbots are the following; prompt injection, jailbreaking, 
offensive prompts, and spamming [6][7]. All of them exploit a 
specific vulnerability in the LLM, namely, its incapacity to 
identify if a given input comes from a system or a user. Thus, 
attackers can manipulate the behavior of a machine learning 
system, evade some safety measures, or try to obtain confidential 
information from L LM. All such kinds of attacks frequently 
happen in real time scenario. A number of approaches have been 
proposed to enhance the security of chatbots like the use of 
prompt engineering and layering filters [4]. The main limitation 
of these techniques is that they depend on the model generating 
the bot responses. Also, there exists a contradiction in the goals 
of the model; the need to provide responses while ensuring that 
the output is secure against adversarial attacks [9]. This 
necessitates an independent security approach to address the 
problem. 
To develop an independent security model for chatbots, this 
work proposes the use of two Large Language Models (LLMs). 
Specifically, in this design, one LLM (LLM-1) serves as a 
classifier which classifies all inputs from the users as either 
prompt injections, jailbreak, offensive, spam, or safe. Using the 
confidence level, LLM-1 ensures that malicious messages are not 
delivered into the system. However, the questions that are marked 
as safe, are forwarded to LLM 2 and answered through the RAG 
approach with constraints. For the LLM-2, the model utilizes the 
data retrieved from a controlled knowledge base, ensuring that 
the answer is truthful and does not allow access to sensitive 
information.  
The separation into two LLMs allows both models to work 
within their own domains while keeping both their performance 
and security intact. The whole process may be called pipe lining, 
as all user input is filtered by LLM-1. All received queries are 
analyzed and evaluated, with only safe ones passed forward to 
LLM-2 to be answered. The proposed approach allows the 
chatbot to retain both safety and security features while remaining 
fully functional.

II. RELATED WORKS 
In this study by Emekci and Budakoglu [6], the authors 
develop a Dual-LLM model to provide access to secure chatbot 
systems. Unlike ordinary chatbots where only one model is used, 
the authors propose dividing response generation into two parts. 
First, a cl assifier to filter out malicious queries or bypassing 
security measures. After passing clean data to another LLM 
model, it will generate the final responses. This Dual -LLM 
technique is useful for ensuring security in chatbot systems, but 
it is difficult to handle ambiguous input requests which could not 
be determined whether the request is malicious or safe. Also, this 
method increases the computational cost and latency time. In the 
review paper by Mehta et al. [5] , the authors  present several 
ways to build a chatbot system powered by LLMs. Multiple 
system architectures have been examined, from low code 
systems to customized systems that involve prompt engineering 
and retrieval-augmented generation. However, security concerns 
and defense against adversarial attacks have not been considered 
in this research paper. 
Kim et al. [3] introduced a security framework for preventing 
the occurrence of unsafe prompts in LLM environments. This 
framework uses the technique of input validation and filtration 
for identifying potential attacks in order to mitigate the problem. 
Another similar work by Muliarevych [4] presents the concept 
of applying LLM -based techniques for detecting prompt 
injections. Specifically, the proposed approach uses model based 
analysis for finding vulnerable points and addressing prompt 
injections. Finally, the work done by Zhang et al  [7] addresses 
prompt injections in robotic systems based on LLMs. Even 
though the above -mentioned research papers offer improved 
protection against prompt injections, they have some limitations. 
They use only one level of protection and can be integrated into  
the model only as a part of the model. Jailbreak attacks have been 
discussed by Feng et al. [8]. The authors suggest that the 
proposed Jailbreak Lens technique can be applied in order to 
visualize and classify models' re sponses to different prompts 
according to the degree of acceptance or refusal of these requests 
like complete acceptance, partial rejection, etc.  
Both full compliance and partial rejection have been 
distinguished, which enabled researchers to learn more about 
attacks on the models. Unfortunately, analysis and 
understanding of vulnerabilities were the main objectives of the 
work mentioned above, and therefore no techniques that could 
prevent attacks in a secure way during the functioning of the 
application were proposed. One of the tools for developing an 
educational chatbot based on language modeling has been 
described by Neumann et al. [ 1]. Students can be taught how to 
operate databases through interactive dialogue. It can be inferred 
from the aforementioned literature that even though there have 
been substantial advancements in the area of chatbots in terms 
of their development, security, and applications, there still exists 
a lack of a holistic approach that guarantees both efficiency and 
effectiveness in the system.  
The most prevailing methods are geared towards either 
functionality or security, but not both. There are various ways to 
secure LLM including filtration of input prompts to the model. 
The existing techniques are one-layer defense strategies that are 
ineffective in dealing with complex attacks. There are security 
solutions to jailbreak attacks which analyze LLM response 
vulnerabilities and finding the best approach to deal with them 
[15]. These meth ods will be useful  only during the analytical 
phase and no a ctual protection will be provided. The 
development of modular chatbots based on RAG proves to be 
better when it comes to scalability and effectiveness [9] [16]. 
A knowledge base of documents using LLM for building 
generative question -answering system was proposed by 
Sawarkar et al. [10]. The blended retriever uses semantic search 
methods within the corpus for retrieving relevant answers. But, 
this method has not b een fine tuned to adapt domain specific 
LLMs. The RAG systems provided a notable performance only 
for smaller contextually aware LLMs. In [11], the authors 
propose the concept of RAG pipelines that combine contextual 
relevance and matching with external kn owledge sources.  This 
work improves the factual accuracy and reduce the 
hallucinations for the generated answers. But, the fragmented 
information in knowledge integration may lead to bias and 
misleading information. The various threats in RAG like prompt 
injection, data poisoning and multilingual threats is common in 
LLMs and proper defense mechanisms has to be incorporated for 
applying RAG in real time systems [12] [13].   
RAG implementations in LLMs suffer limited precision in 
retrieval, high computational time and resource costs [17]. To 
minimize the computational load, a question answering system 
can be developed based on the internal documents provided by 
the organizatio n. This improves the retrieved chunk relevance 
and also provides more accurate answers for the chatbot. The 
correctness of the answers provided by the chatbot LLM is based 
on how the LLM evaluates its own output and perform error 
correction before providin g answers [18]. Edge Intelligence 
incorporated with LLM can provide response generation similar 
to humans [20]. The coordination between multiple components 
of these systems may incur high computational complexity and 
the errors if remains uncorrected in one stage will lead to 
incorrect answers and reduced efficiency in real time 
applications. 
The authors  [19] discuss on multi -model architectures to 
ensure a proper separation between security and response 
generation, thus improving the filter mechanism against the 
malicious queries. Nonetheless, it fails to provide mechanisms 
for handling the ambiguous queries from users who cannot 
properly communicate their intentions and may lead to a 
misclassification problem. Also, while application centric 
chatbots improve usability, they fail to include robust security 
mechanisms required before deploying them in accessibl e 
settings. One of the main limitations of existing solutions is the 
failure to create a complete secure pipeline for the LLM system. 
Although the input validation problem has been tackled, there 
are still no constraints imposed during response generation,  
which makes them vulnerable to problems like hallucinations 
and data leakage. Moreover, real -time detection and analysis of 
threats are crucial for security.

In order to overcome these issues, this research paper 
proposes a novel dual LLM structure that includes a separate 
security mechanism. First, a classification model called LLM -1 
is employed, analyzing the incoming query in real -time using 
threat classes and confidence levels, stopping any harmful inputs 
from being processed. Subsequently, safe queries are allowed to 
proceed to the second phase in the LLM -2 module, working 
under constraints of the RAG model. Using a restricted 
knowledge base for generating replies, this technique guarantees 
precise outputs without any hallucinations and data leaks, 
ultimately providing a complete and safe chatbot system. It is 
worth noting that this approach not only enhances resistance to 
any types of adversarial attacks bu t also provides outstanding 
performance results in an open-source environment. 
III. METHODOLOGY 
The architecture of the proposed Secure Retrieval 
Augmented Conversational System  (SRACS) generates 
responses for the University I nformation Assistant that are 
highly secure. This system contains two levels of large language 
models, apart from the RAG system, decision control, and 
administration monitoring system.  All the requests made by 
users will go through various checks before responses are 
provided to make sure that any problems with injections, 
jailbreaks, or other forms of abuse of the prompt system  are 
mitigated. The work flow is of the proposed SRACS system is 
designed as a secure Dual-LLM Chatbot as illustrated in Fig 1.

In the proposed SRACS system, first, a user sends a query 
through the interface of the chat application. At the stage of 
input processing, the user's session is managed and validated 
using the system control module. Next, the system passes the 
validated query to the LLM -1 to perform the security 
classification operation. Specifically, the query is checked for 
prompt injection, jailbreaking, offensive behavior, and spam  
[15]. Based on the analysis results, and a confidence 
threshold, the system classifies th e request as safe or 
malicious. If the request is categorized as malicious, then its 
parameters are logged as the attack type and time stamp, and 
a non-informative safe response is generated. 
 If the request is classified as safe, the system continues 
with the retrieval -augmented generation procedure. The 
query is submitted to the FAISS vector store and filtered 
based on the similarity search algorithm and sensitive data 
detection criterion. Finally, the information is processed by 
LLM-2 to  generate the controlled output and t he output is 
validated prior to its delivery to the end -user. The system’s 
operations, such as query, decision -making and threat 
detection, are constantly analyzed and logg ed in the admin 
analyst’s dashboard. The  different phases in the proposed 
work include input handling and session management, 
security classification using LLM, retrieval augmented 
response generation, and administration monitoring system. 
Although the proposed Dual -LLM architecture improves 
security, introducing multiple security stages can increase 
computational latency. To reduce this overhead, a lightweight 
preliminary filtering layer is implemented before LLM -1. 
Safe educational queries are fast-tracked without unnecessary 
deep analysis, while only suspicious queries undergo 
advanced security classification. This optimization improves 
response efficiency and supports real-time deployment. 
A. Input Processing and Session Management 
This system starts by allowing users to interact using the 
Stream-lit chat interface where questions regarding college 
facts are provided in natural language. The inputs go through 
the input validation process and confirms that it does not 
contain any misinformation or blank data. The  session 
awareness maintains the interaction between the user and the 
system that spans over several conversations.  
B. Preliminary security  
The preliminary filtering stage serves as a security gate in 
the Dual-LLM system architecture. This filtering stage is 
purely based on rules and doesn’t use any language model; 
therefore, it is very efficient and works fast. The purpose of 
the module is to identify whether a given request is 
considered safe, harmful, or sus picious. To accomplish this 
task, the module utilizes predefined rules and employs pattern 
recognition and regular expression methods to filter the data 
provided by a user.  
As a result, a query will either be classified as SAFE, 
BLOCKED, or SUSPICIOUS.  However, any obvious and 
harmless questions, which fall under common topics, are 
tagged as safe and goes through the response generation stage. 
For those cases where the input cannot be categorized into 
these two classifications, they would be categorized as 
suspicious and sent to LLM -1. The objective of this stage 
includes identifying indirect attacks or other unusual inputs, 
such as disguised threats, among others. The code fo r 
preliminary security classification.

D. Retrieval-Augmented Generation Retriever 
In case of permitted queries, the system employs a 
Retrieval-Augmented Generation model for improving the 
quality of the generated response. The user’s input is turned 
into the embedding and used to perform similarity search 
over a vector database in FAISS  that consists of information 
which are domain specific like universities, finance, 
healthcare, etc., After retrieving contextually related chunks, 
the system performs extra filtering out of the chunks that may 
contain sensitive information.  
Finally, this retrieved context is combined with the input 
of the user, which constitutes the grounded input used for the 
model generating the response.  To mitigate indirect prompt 
injection through retrieved documents, the framework applies 
controlled retrieval policies, similarity filtering, sensitive -
content validation, and restricted context injection before 
response generation. This ensures that only  trusted and 
domain-relevant information is supplied to LLM -2.  The 
process of RAG Retriever is depicted.

FUNCTION retrieve_context(query): 
     IF is_sensitive_query(query) == True: 
          RETURN "BLOCKED" 
     results = FAISS_search(query) 
     IF results is empty: 
          RETURN "NO DATA" 
     RETURN results 
END

The query structured by the user together with the context 
retrieved by the RAG is given as input to the LLaMA 3 which 
then produces a relev ant answer to the user’s request. This 
answer is provided in a structured manner to enhance its 
readability and understanding for the user.

F. Logging and Admin Monitoring System 
This system is developed with a detailed logging facility 
which records all user interactions, whether allowed or 
blocked requests. This log consists of information like date -
time stamp, request contents, type of classification made, 
nature of attack, confidence level, and overal l status of the 
transaction. These logs are further used by the administration 
monitoring facility of this system, which consists of log 
viewing and filtering, performance measurement, and other 
similar functionality. Moreover, the administrator’s 
dashboard consists of an advanced facility of complete data 
access and an admin own LLM, where any type of 
questioning can be performed without any limitations.

V. CONCLUSION  
In this research, a new approach is designed to build a 
secure chatbot application based on a Dual-LLM structure to 
overcome the security challenges arising of the open-source 
LLM chatbot. The modern applications are currently faced 
with different types of challenges, like prompt injection, 
jailbreak attack, and malicious user prompts, since there is no 
special security component that guarantees safety from these 
problems. Therefore, the proposed SRACS model is designed 
to introduce a threat detection and reaction mechanism using 
dual LLM. The LLM -1 will classify the type of threat and 
assigns the corresponding confidence score based on the pre-
classified types of threats. The LLM-2 is designed to generate 
responses in the context of limited RAG architecture. The 
SRACS-LLM methodology has proved to be highly effective 
in terms of improving threat detection and reducing the 
number of unsafe responses. Research related to scalability is 
a prerequisite for real-time operation and research on response 
validation and domain security models used by chatbots will 
be further perceived as an extension and future work. Areas of 
enhanced management of ambiguities within query 
processing and usage of adaptive learning mechanisms could 
be studied and worked as a future scope of this research work.
