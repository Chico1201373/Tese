Abstract—Generative AI tutors are attractive for universities
that lack enough human tutoring capacity, but unbounded cloud
chatbots are difficult to audit, costly to operate, and risky
when advice is not grounded. This paper presents a cloud-edge
retrieval-augmented agent tutor for trustworthy personalized
learning in resource-constrained higher education. The workflow
combines early-risk learning analytics, local evidence retrieval,
policy checking, route-aware cloud escalation, and an explicit
run record. On the Open University Learning Analytics Dataset
(OULAD), the executed pipeline processed 32,593 student-course
records, produced 8,149 test predictions, audited 160 high-risk
feedback cases, and generated a full-test routing audit. Logistic
regression achieved Macro-F1=0.757, AUC=0.838, and at-risk
recall=0.693 from first-28-day activity; across five split seeds,
Macro-F1 was 0.757 ±0.002. Feature ablation, query ablation,
and route-policy stress tests identify which design choices matter.
The contribution is a reproducible AIoTC-style architecture
and evidence package, bounded to offline public-data evalua-
tion rather than classroom learning gains or hardware latency
benchmarking.

I. I NTRODUCTION
Universities are rapidly testing generative AI for tutoring
and feedback, including large-scale automated feedback for
language learning [1], [2]. The education literature is also
cautious about hallucination, academic-integrity, transparency,
and governance risks [1]. These risks are sharper in resource-
constrained institutions. A useful AI tutor must personalize
support, but it cannot send every learner interaction to a cloud
model or issue advice that cannot be traced to evidence.
Three technical streams are relevant but often remain sep-
arate. Learning analytics can identify learners who may need
early support [3]–[5]. Retrieval-augmented generation (RAG)
can ground generated language in external evidence, although
retrieval does not remove the need for faithfulness evalua-
tion [6]–[8]. LLM-agent work provides a way to separate
sensing, tool use, policy checking, and response composi-
tion [9]. Edge intelligence and mobile-edge LLM research
further motivate routing some computation away from the
cloud when latency, privacy, bandwidth, or cost matters [10],
[11].
This paper joins these streams into a compact AIoTC
education service. The technical novelty is a logged control
loop linking risk scoring, course-context retrieval, evidence-
marker auditing, policy blocking, and cloud-edge routing for
one learner record. This differs from educational RAG that
mainly grounds answers and learning analytics that mainly
predicts risk. This positioning is consistent with recent work on
auditability in AI-integrating learning-analytics systems [12].
We contribute (i) a route-aware RAG agent architecture, (ii)
a reproducible OULAD experiment with prediction, ablation,
retrieval, agent, and routing artifacts, and (iii) an explicit claim
boundary that avoids unperformed classroom, human-rating, or
edge-device claims.

The routing audit was run on the full 8,149-record test
set. The default policy assigned 60.4% of records to edge-
only handling, 13.7% to edge-first cloud summary, and 25.9%
to cloud-assisted handling. Route-policy stress tests changed
cloud-call share from 31.5% under a cloud-sparing policy
to 50.0% under a support-intensive policy and 83.8% under
a retrieval-strict policy. These values indicate a controllable
resource-support trade-off; they should not be read as device
benchmarks.
IV. D ISCUSSION
The results support the design choice of treating learner-
facing AI as an auditable service. Learning analytics supplies

a support trigger, RAG supplies evidence grounding, the agent
trace supplies governance, and route-aware delivery supplies
resource control, consistent with calls for ethical educational
AI [13].
The strongest evidence is reproducibility: the same script
regenerates the feature table, model metrics, seed checks, abla-
tions, feedback audit, route audit, and figures from public data.
The run transcript records the command, software versions,
row counts, scores, audit rows, and figure outputs, making the
architecture checkable rather than conceptual.
The evidence is intentionally conservative. The selected
model is not claimed to be best in all settings; it is selected
because it gives the best Macro-F1 in this run and the
highest at-risk recall among tested compact baselines. The
feedback audit checks grounding, prohibited inferences, and
template actionability, but not free-form conversation, learner
satisfaction, or teaching effectiveness.
The main deployment boundary is cloud-edge measurement:
the route audit covers every test record, but latency and
token values remain proxies. Deployment still requires edge-
device profiling, network measurements, human ratings, and
institutional review before classroom-impact claims.
For AIoTC education systems, this boundary is useful.
The workflow turns a tutor into inspectable decisions: which
learners were flagged, which evidence passages were retrieved,
which claims were allowed, and which route handled the
request. The recall-gap warning is a deployment gate: adminis-
trators review subgroup recall before launch, adjust thresholds
or add human review when gaps persist, and never use the
flag for punitive automation. Prediction remains a support
trigger rather than an automated intervention. Route thresholds
can change without retraining the predictor, helping resource-
constrained universities audit the service before live teaching.
V. C ONCLUSION
This paper presented a cloud-edge RAG agent tutor for trust-
worthy personalized learning in resource-constrained higher
education. In a reproducible OULAD experiment, risk an-
alytics, evidence-grounded feedback, and edge-first routing
produced an inspectable AIoTC workflow under a conservative
claim boundary. Future deployment work should test class-
room learning gains and hardware latency.
